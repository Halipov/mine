# Mine Launcher

Минимальный лаунчер для модовой сборки Minecraft на Fabric. Друг скачивает
один файл, вводит ник и жмёт «Играть»: лаунчер сам приносит нужную версию
игры, Java, загрузчик Fabric и моды, а сервер уже стоит в списке сетевой игры.

Аккаунт Mojang не нужен — вход оффлайновый, по нику.

Это только клиентское приложение. Сборкой (составом модов, версией игры) и
раздачей файлов управляет [соседний проект сервера](../mine-server) — он же
их и хостит.

## Что умеет

- **Обновляется сам.** Состав модов, версия игры и адрес сервера живут в
  манифесте на сервере. Меняешь манифест — у всех при следующем запуске
  подтягивается новое. Обновлять сам лаунчер для этого не требуется.
- **Не трогает чужое.** Лаунчер помнит, какие файлы положил он сам, и удаляет
  только их. Мод, который игрок докинул в `mods` вручную, переживёт любое
  обновление сборки.
- **Приносит свою Java.** Скачивает JRE нужной версии с Adoptium под нужную
  платформу, включая Apple Silicon. Системную Java не трогает и не требует.
- **Ставит только своё.** Манифест общий с сервером, у каждого мода помечена
  сторона — чисто серверные моды на клиент не поедут.
- **Профили.** Несколько ников с переключением. UUID считается так же, как в
  самом Minecraft (`OfflinePlayer:<ник>`), поэтому сервер узнаёт того же
  игрока после переустановки.
- **Память.** Ползунок с потолком по объёму памяти машины и разумными
  флагами G1 для модовой сборки.
- **Сервер в списке.** Пишется в `servers.dat` первым, свои серверы игрока
  сохраняются. Есть галочка «подключиться сразу» — минуя главное меню.

## Быстрый старт

```bash
npm install
npm run dev
```

Проверить, что весь конвейер работает, не запуская игру:

```bash
npm run selftest           # без ресурсов игры, ~200 МБ
npm run selftest -- --full # вместе с ресурсами
```

Самопроверка собирает временную сборку из свежих версий с Modrinth, так что
работает и без запущенной раздачи. Чтобы прогнать её на настоящей сборке:

```bash
SELFTEST_MANIFEST=../mine-server/web/pack.json npm run selftest
```

## Настройка

Единственный файл — [`src/shared/config.ts`](src/shared/config.ts):

```ts
baseUrl: 'http://127.0.0.1:8080'
```

Это корень раздачи: оттуда берутся манифест сборки (`/pack.json`) и
обновления лаунчера (`/launcher/latest.json`). Локально раздачу поднимает
`npm run serve` в проекте сервера, потом здесь прописывается его домен.

Адрес вкомпилирован намеренно: лаунчеру неоткуда узнать его до первого
запроса. Игрок может переопределить манифест в настройках — поле понимает и
ссылку, и путь к локальному файлу, что удобно для обкатки.

## Выпуск новой версии

Нужен, только когда меняется сам лаунчер, а не состав модов.

```bash
npm version patch
npm run pack:win            # на Windows
npm run pack:mac            # на макбуке
```

Затем в проекте сервера:

```bash
npm run publish-launcher
```

Он разложит сборки в `web/launcher/`, посчитает SHA-256 и обновит
`latest.json`. Лаунчер у друзей найдёт обновление во вкладке «О лаунчере» и
проверит контрольную сумму перед установкой.

Сборки под разные платформы делаются на разных машинах, поэтому
`latest.json` дополняется, а не перетирается: собрал на Windows — обновилась
запись `win-x64`, macOS осталась от прошлого раза.

Если макбука под рукой нет — [GitHub Actions](.github/workflows/release.yml)
соберёт macOS-версию по тегу `v*` или по кнопке и отдаст артефактом запуска.
Скачать, распаковать в `dist/` и прогнать `publish-launcher`.

## Если не запускается или не собирается

**`npm : Невозможно загрузить файл npm.ps1, выполнение сценариев отключено`.**
Политика выполнения PowerShell, к проекту отношения не имеет. Либо звать npm
батником — `npm.cmd run dev`, — либо один раз разрешить скрипты для своего
пользователя (без прав администратора):

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

**`Cannot create symbolic link ... libcrypto.dylib` при сборке.**
electron-builder распаковывает пакет `winCodeSign`, внутри которого лежат
символические ссылки для macOS, а Windows не даёт их создавать без прав
администратора или режима разработчика. Распаковать пакет в кеш заранее,
пропустив ненужные на Windows файлы:

```powershell
$cache = "$env:LOCALAPPDATA\electron-builder\Cache\winCodeSign"
New-Item -ItemType Directory -Force -Path $cache | Out-Null
Invoke-WebRequest -OutFile "$cache\winCodeSign-2.6.0.7z" `
  'https://github.com/electron-userland/electron-builder-binaries/releases/download/winCodeSign-2.6.0/winCodeSign-2.6.0.7z'
& .\node_modules\7zip-bin\win\x64\7za.exe x "$cache\winCodeSign-2.6.0.7z" `
  "-o$cache\winCodeSign-2.6.0" '-xr!darwin'
```

Найдя готовую папку в кеше, electron-builder не станет качать пакет заново.
На раннерах GitHub Actions этой проблемы нет.

**Окно Electron не открывается, а в консоли ошибка про `app.setName`.**
В терминале редактора живёт переменная `ELECTRON_RUN_AS_NODE=1`, из-за которой
Electron стартует как обычный Node. Все npm-скрипты идут через
[scripts/run.mjs](scripts/run.mjs), который её вычищает; если запускаешь
`electron` руками — сбрось её сам.

## macOS

Сертификата Apple Developer у проекта нет, отсюда две особенности.

**Первый запуск.** Приложение подписано ad-hoc — на Apple Silicon без этого
оно бы вообще не запустилось. Но нотаризации у него нет, и Gatekeeper
встретит окном «Apple could not verify "Mine Launcher" is free of malware».

Обойти можно тремя способами. Первый работает везде и надёжнее прочих:

```bash
xattr -dr com.apple.quarantine "/Applications/Mine Launcher.app"
```

Через интерфейс, **macOS 15 Sequoia и новее**: System Settings → Privacy &
Security → пролистать вниз до «Mine Launcher was blocked…» → Open Anyway.

**macOS 14 Sonoma и старее**: правый клик по приложению → «Открыть» →
«Открыть». В Sequoia Apple этот обход убрала, там только два пути выше.

Всё это делается один раз на установку. Обновления лаунчер ставит сам, а
файлы, скачанные приложением, карантин не получают — повторно окно не
появится.

**Друзьям проще скачивать через терминал.** Карантин ставят браузеры и почта,
а `curl` — нет, поэтому окна не будет вовсе:

```bash
cd ~/Downloads && curl -LO http://193.124.224.225/launcher/MineLauncher-0.1.2-mac-arm64.zip
unzip -q MineLauncher-0.1.2-mac-arm64.zip -d /Applications
```

Для Intel-маков — файл с `mac-x64` в имени.

**Убрать предупреждение совсем** можно только сертификатом Apple Developer
($99 в год) с нотаризацией. Для сборки на пятерых это едва ли оправдано, но
если Mac-друзей много и объяснять каждому надоест — вариант рабочий.

**Обновление.** Штатный механизм Electron требует настоящей подписи, поэтому
лаунчер обновляет себя сам: качает zip, подменяет бандл и перезапускается.
Файл, скачанный самим приложением, карантин не получает, так что Gatekeeper
к обновлению не придирается. Раздача своя, поэтому целостность проверяется
по SHA-256 из `latest.json`.

## Где лежат данные

- Windows — `%APPDATA%\Mine Launcher`
- macOS — `~/Library/Application Support/Mine Launcher`

Внутри: `shared/` (версии, библиотеки, ресурсы — общие для всех сборок),
`runtime/` (скачанная Java), `instances/<id>/` (папка игры: моды, конфиги,
сохранения), `settings.json`.

## Устройство

```
src/main/core/
  http.ts        загрузка: пул потоков, проверка хешей, докачка, ретраи
  mojang.ts      version_manifest, version.json, client.jar, ресурсы
  fabric.ts      meta-API Fabric: версия загрузчика и профиль
  version.ts     правила Mojang, слияние профилей, разбор библиотек
  java.ts        JRE с Adoptium под платформу
  natives.ts     распаковка нативных библиотек (для версий до 1.19)
  sync.ts        синхронизация модов с реестром «наших» файлов
  servers.ts     запись servers.dat (NBT) с сохранением чужих серверов
  launch.ts      подстановка аргументов, classpath, запуск JVM
  installer.ts   весь конвейер по шагам
src/main/
  selftest.ts    прогон всего конвейера без запуска игры
  updater.ts     самообновление с проверкой SHA-256
```

## Ограничения

- Только Fabric. Forge и NeoForge требуют прогона installer-процессоров с
  патчингом клиента — это отдельная и сильно большая история.
- Только оффлайн-вход. Для игры на своём сервере с `online-mode=false` этого
  достаточно; на официальные серверы с таким лаунчером не попасть.
